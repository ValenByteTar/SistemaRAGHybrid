Zero Trust Architecture — Principles and Implementation

Zero Trust is a cybersecurity paradigm that shifts security from a perimeter-based
model to a resource-based model. The core principle of Zero Trust is "never trust,
always verify" — no entity, whether inside or outside the network, is trusted by
default. Every access request must be authenticated, authorized, and continuously
validated before granting access.

The Zero Trust model was originally developed by John Kindervag at Forrester Research
in 2010. NIST formalized the concept in Special Publication 800-207, "Zero Trust
Architecture," published in August 2020.

Core Principles of Zero Trust:

1. Verify Explicitly — Always authenticate and authorize based on all available data
   points, including user identity, location, device health, service or workload,
   data classification, and anomalies.

2. Use Least Privilege Access — Limit user access with Just-In-Time and
   Just-Enough-Access (JIT/JEA), risk-based adaptive policies, and data protection
   to help secure both data and productivity.

3. Assume Breach — Minimize blast radius and segment access. Verify end-to-end
   encryption, use analytics to get visibility, drive threat detection, and improve
   defenses.

Zero Trust Architecture Components:

- Policy Decision Point (PDP) — The central component that evaluates access requests
  against policies. It uses signals from identity providers, device management systems,
  and threat intelligence to make access decisions.

- Policy Enforcement Point (PEP) — The component that enforces the decisions made by
  the PDP. It sits between the user and the resource and blocks or allows access
  based on the PDP's decision.

- Trust Algorithm — The logic that the PDP uses to compute a trust score based on
  signals such as user identity, device posture, location, time, and behavioral
  analytics.

Implementation Pillars (per CISA Zero Trust Maturity Model 2.0):

1. Identity — Strong authentication, MFA, conditional access, and identity governance.
2. Devices — Device inventory, compliance checking, and endpoint detection and
   response (EDR).
3. Networks — Network segmentation, micro-segmentation, and encrypted traffic.
4. Applications — Application security, API protection, and secure development.
5. Data — Data classification, encryption, data loss prevention (DLP), and
   information rights management.

Maturity Levels: Traditional, Initial, Advanced, and Optimal. Organizations are
expected to progress through these levels iteratively, starting with the most
critical assets and expanding outward.
